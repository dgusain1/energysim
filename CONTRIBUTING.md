# Contributing to energysim

Thanks for helping improve energysim. This guide covers setup, tests, style, and the two most
common extension points: physical models and simulator adapters.

## Setup

energysim uses a `src/` layout and hatchling for builds. Python 3.10 or newer is required.

```bash
git clone https://github.com/dgusain1/energysim.git
cd energysim
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
python -m pip install -e ".[dev]"  # tests, ruff, mypy, build, twine
```

Optional simulator back-ends are separate extras: `fmu`, `powerflow`, `pypsa`, `opendss`,
`plotting`, or `all`. Install them when you work on the code paths that need them.

## Running tests

```bash
python -m pytest tests                  # everything that runs locally
python -m pytest tests -m "not slow"    # quick loop
python -m pytest tests --cov=energysim  # with coverage
```

CI runs the test matrix on Ubuntu and Windows for Python 3.10 to 3.13 (3.14 is allowed to
fail), a full run with all extras, an Octave job, a strict docs build, and a package check.
A weekly job runs the validation suite.

## Style and linting

- Lint with `ruff check src tests`. The configuration lives in `[tool.ruff]` in `pyproject.toml`.
- Keep lines to 120 characters or fewer.
- Use type hints where they help readers. The package ships `py.typed`; mypy is configured
  permissively in `pyproject.toml`.
- Do not use `eval`, `exec`, or pickle loading of data that is not trusted. See `SECURITY.md`.
- Do not add state rollback to simulator adapters. Iterative coupling was removed in 3.0.

## Adding a physical model

1. Subclass `ModelComponent` from `src/energysim/models/common/base_component.py`. It is a
   `SimulatorAdapter`, so implement the same lifecycle methods (`configure`, `init`, `step`,
   `get_value`, `set_value`, and so on).
2. Put the class in the matching module under `src/energysim/models/` (for example `storage.py`
   for storage technologies), or in a new module if none fits.
3. Expose a named preset in `src/energysim/models/catalog.py` if users are likely to want one.
4. Add tests to `tests/` (see `tests/test_models_framework.py` for shared model checks).
5. Document the model in `docs/components/` and add it to the component index.

## Adding a simulator adapter

1. Create `src/energysim/<name>Adapter.py` (or `<name>_adapter.py`, following the neighbouring
   modules). Implement `SimulatorAdapter` from `src/energysim/base.py`.
2. Register it with `world` by adding an `add_<name>` method or by extending `add_simulator`
   in `src/energysim/world.py`.
3. If the adapter runs arbitrary code or native binaries, add it to the unsafe set so that
   `--safe` refuses it (see `UNSAFE_SIM_TYPES` in `world.py`).
4. Add tests and a page under `docs/`, and link it from `docs/add-simulator.md`.

## Adding a docs-tested example

Examples are rendered into the documentation, and the docs build runs in strict mode.

1. Add a scenario YAML under `examples/scenarios/`, or a notebook under `examples/notebooks/`.
2. Notebooks are generated by `scripts/generate_notebooks.py`. Edit the generator and re-run
   it rather than editing the notebook by hand.
3. Reference the example from a page in `docs/` so `mkdocs build --strict` covers it.
4. Run `energysim validate <file>` on any new YAML scenario before opening a pull request.

## Changelog

Add an entry under the unreleased heading in `CHANGELOG.txt`.

## Pull requests

- Keep each pull request focused on one change.
- Use the pull request template. Tick the checklist honestly.
- Make sure CI is green before requesting review.
